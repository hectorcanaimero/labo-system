## 🛠️ Technical Infrastructure (Verified)

### Health Endpoints

✅ `GET /api/pdf/health` (apps/web/app/api/pdf/health/route.ts)
- Public health check (no auth)
- Verifies Postgres connection
- Logs `pdf_health_ok` metric

✅ `GET /api/health` (InsForge backend)
- Already running on https://insforge.rvlaboratorio.com/api/health
- Returns status, version, timestamp

### Cron Jobs (Route Handlers)

✅ `POST /api/cron/scrape-bcv` (apps/web/app/api/cron/scrape-bcv/route.ts)
- Daily at 13:00 UTC (09:00 VET)
- Scrapes bcv.org.ve with fallback to DolarAPI
- Persists to `tasa_cambio_bcv` table
- Logs to audit_log

✅ `POST /api/cron/check-stale-tasa` (apps/web/app/api/cron/check-stale-tasa/route.ts)
- Daily at 18:00 UTC (14:00 VET)
- Checks if BCV rate > 48h old
- Emails all admin users if stale
- Idempotent (max 1 alert per day)
- Logs to audit_log

✅ `POST /api/cron/cleanup-exports` (apps/web/app/api/cron/cleanup-exports/route.ts)
- Weekly (Sundays 03:00 UTC)
- Removes export files > 7 days old
- Logs to audit_log

### Admin Dashboard

✅ `GET /app/audit` (apps/web/app/(app)/audit/page.tsx)
- Audit log viewer for Admin only
- Filters by user, action, entity, date
- Paginated (25/50/100 records)
- Shows activity, errors, creations

## ⚠️ Risk Mitigation

### If Uptime < 99.5% on Day 15

1. Identify downtime events in UptimeRobot
2. SSH to VPS: `docker logs --since 15d <container>`
3. Check Postgres health, network, application errors
4. Create P0 issue if not already tracked
5. Plan hotfix with Dev

**Action**: Extend checkpoint, replan next week

### If P0/P1 Found After Day 15

- Verify fix is in production (git log, docker image tag)
- Re-run smoke tests to confirm
- Update POST-CUTOVER-METRICS.md with incident summary
- Continue to Day 30 checkpoint
