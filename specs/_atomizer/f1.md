### F1.1.T2 — Upload de assets (logo, firma, sello) a InsForge Storage

**Objetivo**

Flujo que permite Admin subir 3 imágenes (logo, firma, sello) al bucket `assets` de InsForge Storage y guardar los object keys en `laboratorio_config`.

**Contexto**

ARCH ADR-01 (storage), ADR-02 (PDFs leen assets vía URL firmada), ADR-11 (InsForge Storage S3-compatible con upload/download strategy). Assets: PNG/JPG ≤ 2 MB (PRD §7 dependencias).

**Alcance**

Sí hace:
- Route Handler `POST /api/config/assets/upload` (Admin only): pide a InsForge la *upload strategy* (URL presignada cuando el backend usa S3) y la retorna junto con el object key generado (`assets/{tipo}/{uuid}.{ext}`).
- Cliente hace `PUT` a la URL presignada y luego confirma; el Route Handler `POST /api/config/assets/confirm` valida MIME image/* y tamaño ≤ 2 MB server-side antes de persistir.
- Handler `POST /api/config/assets/set` que actualiza el campo correspondiente (`logo_object_key`, `firma_object_key`, `sello_object_key`) en `laboratorio_config`.
- Al reemplazar asset: borrar el objeto anterior de storage (Delete Object de InsForge).
- Handler `GET /api/config/assets/url?type=` retorna URL firmada vía *download strategy* (TTL ~1h).

No hace:
- Recorte/redimensionado.
- Preview (UI en T04).

**Criterios de aceptación**

- [ ] Upload de PNG 500KB funciona; el objeto queda en bucket `assets`.
- [ ] Upload de archivo > 2 MB rechaza cliente + rechaza confirm (defense in depth).
- [ ] Upload de PDF (mime incorrecto) rechaza.
- [ ] `GET /api/config/assets/url` retorna URL válida por 1h.
- [ ] Reemplazar logo borra el archivo anterior.
- [ ] Operador rechazado.

**Notas técnicas**

InsForge retorna la estrategia (presigned o direct) según configuración `S3_USE_PRESIGNED_URLS`; el flujo del cliente debe leerla de la respuesta, no asumirla. Helper compartido en `packages/lib/storage.ts`.
