# S3 · @react-pdf server-side runtime

## Objetivo

Validar la decisión de ARCH ADR-02: **renderizar los PDFs con `@react-pdf/renderer` en un Next.js Route Handler (Node runtime)** en vez de en Convex action. Medir latencia end-to-end, bundle size, comportamiento con assets remotos (logo/firma/sello desde Convex File Storage), y streaming al cliente.

## Contexto

- PRD §5 fija stack: `@react-pdf/renderer` (sin Puppeteer, sin Chromium).
- ARCH ADR-02 propone Next Route Handler; Convex action Node runtime es Plan B.
- NFR: PDF ≤ 3 s p95.
- Assets del laboratorio viven en Convex File Storage (URLs firmadas TTL).

## Alcance

Sí hace:
- POC Next.js Route Handler bajo Node runtime que:
  - Lee token de sesión de cookie.
  - Llama Convex query con `ConvexHttpClient` server-side.
  - Renderiza `<ResultadoPDF/>` mínimo con `ReactPDF.renderToStream`.
  - Streamea `application/pdf` al cliente.
- Medir cold-start y warm p50/p95 en Vercel preview (10 runs).
- Medir bundle size del Route Handler.
- Validar carga de asset remoto (logo PNG desde Convex File Storage) — con y sin cache in-memory (TTL 5min).
- Comparar contra POC alterno en Convex action (`"use node"`) para tener número de referencia.
- Documentar helper `convexServerClient(token)` que reusarán F2.resultados y F2.presupuestos.

No hace:
- Implementar `ResultadoPDF.tsx` / `PresupuestoPDF.tsx` finales (eso es F2).
- Optimizar fuentes custom (usar fuentes default por ahora).
- Streaming avanzado (chunked transfer) más allá del default de `renderToStream`.

## Criterios de aceptación

- [ ] POC funcional en `apps/web/app/api/pdf/spike/route.ts` que genera un PDF de 1-2 páginas con datos hardcoded + 1 imagen.
- [ ] Medición documentada: cold p95, warm p95, bundle size, memoria pico.
- [ ] p95 warm < 3s cumplido (o alerta si no).
- [ ] Cache in-memory de assets funcional con TTL 5min (invalidación manual verificada).
- [ ] Helper `convexServerClient(token)` implementado en `apps/web/lib/convex-server.ts`.
- [ ] Comparativa Route Handler vs Convex action documentada con decisión final.
- [ ] Lista de gotchas encontrados (SSR imports, `"use node"` en Convex, tree-shake, etc.).

## Learning outputs

- Confirmación (o refutación) de ADR-02.
- Contrato exacto del Route Handler para `F2.resultados.T*` y `F2.presupuestos.T*`.
- Estrategia de cache de assets reutilizable.

## Blocked features

- F2.resultados.T* (todos los tasks que tocan PDF)
- F2.presupuestos.T* (todos los tasks que tocan PDF)

## Notas técnicas

- `@react-pdf/renderer` es ~15MB. Vercel Route Handler Node runtime lo soporta.
- Necesita `runtime = 'nodejs'` en el Route Handler (no `edge`).
- Convex `ConvexHttpClient` desde Node: usar `NEXT_PUBLIC_CONVEX_URL` + token de la cookie.
- Registrar métrica `pdf_render_duration_ms` desde el Route Handler.
