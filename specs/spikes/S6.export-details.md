# S6 · Exportación CSV/XLSX

## Objetivo

Cerrar el detalle de la feature F10 Exportación (mapea a `F3.export.T*`): formato v1, scope de columnas, performance con 500-10.000 filas, y validar la decisión de ARCH ADR-09 (**CSV en v1** vía Convex action → File Storage → URL firmada).

## Contexto

- PRD §4 F10 y §10 (S6) — cliente pidió exportación XLSX/CSV; contador consume XLSX preferentemente.
- ARCH ADR-09: v1 = CSV con `papaparse` o serialización manual; XLSX (SheetJS) queda para Fase 2 con mismo pattern.
- Volumen: 500 (presupuestos actuales) hasta 10k (proyección).

## Alcance

Sí hace:
- Confirmar con cliente/Admin: ¿CSV alcanza en v1 o XLSX es obligatorio?
- Definir columnas de cada exporte (Pacientes / Presupuestos / Resultados / Costos):
  - Nombre exacto de columnas (header row).
  - Formato de fechas (`YYYY-MM-DD` vs `DD/MM/YYYY`).
  - Formato de números (separador decimal `.` vs `,`, separador miles).
  - Encoding (UTF-8 BOM sí/no para Excel-friendly).
- Prototipar el action `exports.presupuestosCSV` con 10k rows sintéticas y medir:
  - Tiempo de generación.
  - Tamaño de archivo.
  - Consumo memoria action (Convex limita).
- Validar el flujo end-to-end: action → `convex.storage.store` → `getUrl` → `window.open`.
- Definir política de cleanup (cron semanal borra > 7d).

No hace:
- Implementar UI de botón "Exportar" (eso es F3.export).
- Implementar XLSX (Fase 2).

## Criterios de aceptación

- [ ] Decisión CSV vs XLSX firmada por cliente para v1.
- [ ] Spec de columnas para los 4 exportes (Pacientes, Presupuestos, Resultados, Costos).
- [ ] POC action `exportPresupuestosCSVSpike` con 10k rows sintéticas.
- [ ] Medición: tiempo de generación, tamaño archivo, memoria pico.
- [ ] Confirmación de que URL firmada de Convex expira (~1h) y funciona con `window.open`.
- [ ] Diseño del cron `cleanupExports` (frecuencia, criterio de borrado).
- [ ] Recomendación: `papaparse` vs serialización manual (comparar bundle size + performance).

## Learning outputs

- Contrato de columnas por exporte.
- POC funcional reusable en F3.export.T*.
- Confirmación de que la arquitectura CSV vía File Storage escala a 10k rows.

## Blocked features

- F3.export.T* (todos)

## Notas técnicas

- Convex action Node runtime: `"use node"` para usar `papaparse`.
- CSV con UTF-8 BOM (`﻿`) hace que Excel abra el archivo con encoding correcto por default.
- Cleanup cron: usar `_creationTime` de storage items + tag `"export"` (agregar metadata al store).
